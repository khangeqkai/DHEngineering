# Clean-up sweep — dead code, merged duplicates, file splits

Date: 2026-09-27. Approved by the user ("agree on all counts").

Every change here is **behaviour-preserving**: nothing a person sees or does in the app may change. A refactor that would change behaviour (ordering of checks, what a reply says, when something saves) is reported, not done.

All paths below are relative to `jobcard-system/` unless they start with `docs/` or `tasks/`.

## Global constraints (every work order)
- **Never run `npm install`, `npm rebuild`, or anything that loads `better-sqlite3` from WSL.** `node_modules` is shared with the Windows side; a rebuild silently breaks the user's app. The server cannot be booted from here — do not try.
- Do not commit. Do not touch files outside your work order's allowed list. If a step needs another file, stop and report.
- Match surrounding code: camelCase, comment density, house style in `/mnt/c/Users/khang/Code/DHEngineering/CLAUDE.md` (read it first).
- Removing a check, guard or comment needs the reason stated in this spec. "Move" means same order, same position in the call sequence.
- No compatibility aliases or re-exports left behind when something moves: repoint every caller.
- Do **not** edit `docs/notes/*.md` or `CLAUDE.md`. Instead, grep them for anything your change makes wrong and list those lines in your report; the coordinator updates docs.
- Verification: `node --check <file>` for every changed/new server `.js`. Client work: `cd jobcard-system/client && npx vite build --outDir <your scratch dir>` (never the default `dist`, other agents build in parallel) and `node jobcard-system/scripts/check-confirmQueue.mjs` if it exists. Paste results.
- Report: numbered list mapping each change to the step number below, anything skipped and why, doc lines that need updating, and `git diff --stat` for your files.

## Frozen decisions
- Equipment Excel export: **delete** (no button, nobody asked for it).
- One-time startup conversions for pre-June-2026 databases: **keep, but move** into `server/src/db/legacyMigrations.js`. They still matter for restoring an old backup.
